# Full audit — 2026-10-01

Each section was produced by an independent pass over HEAD `9aa3c6e`. Sections do not reuse each other's content; they only point to each other by number. Line numbers are approximate.

How findings were checked: "verified" means reproduced by running code (node harnesses or headless Chromium). "Unverified" means read from the source but not executed. The earlier audit files in the repo root were not used as input.

## 0. The notes problem (reported by the user)

"Selected notes are not translating into what appears in game" has more than one cause. All are listed here because the symptom can come from any of them. The root causes also appear in §1 as bugs N1-N7.

There are two things a user could mean by "notes":

* **A. The note template** (the 19 tick boxes under *Note template*, `cfg.noteLines`). Five defects, all reproduced.
* **B. "My notes"** (the textarea on a player page, `state.notes`). These are **never written to the export** (verified: nothing in `exportFile` reads `state.notes`; the only reader is `views.js:5018`). Whatever the user types never reaches BBGM. See §6 item 2.

What BBGM does with a note, checked against zengm source (`augmentPartialPlayer.ts`, `handleUploadedDraftClass`): `note` is kept on import, and `noteBool = 1` is set when it is non-empty. So what the tool exports is what the game stores. Not verified: where the game shows it, or whether the game keeps the `\n` line breaks when it displays a note. The tool writes one line per selected template item, so if the game collapses newlines the lines will run together.

## 1. Bugs

### Notes pipeline (found by the main reviewer, verified in node and in the real UI)

**High**
* **N1. Unticking every box silently restores the 7 defaults.** `js/config.js:609` (`if (!cfg.noteLines.length) cfg.noteLines = DEFAULTS.noteLines.slice()`). In the UI the boxes stay unticked while notes are still written with summary, team, traits, stats, shooting, signature and awards. Verified: with all boxes cleared, `#noteLines input:checked` is 0 and the note still has 7 lines. "No notes" can only be reached through *Include scouting notes in the export*, which is off the sidebar. Fix: allow an empty list (a legitimate "no notes" state) and make the engine write no `note` for it. Or disable the last tick.
* **N2. In Universe mode, changing the note template does nothing.** `js/app.js:4733` builds the season's config from `saved.settings` (frozen when the chain ran), so `noteLines` is the old list. The notes-only shortcut at `app.js:5170-5176` updates only `state.universe.settings`. The comment at 5170 says `universeCfgFor` "reads the live noteLines"; it does not. Verified: with 2 files in Universe mode, unticking *Scouting traits* leaves "Scouts note…" in the notes; the same action with Universe mode off removes it. Export writes the stale text too. Fix: `cfg.noteLines = state.cfg.noteLines.slice()` inside `universeCfgFor`.

**Medium**
* **N3. The summary line repeats lines you did not choose.** `js/engine.js:5747-5785`. The one-sentence summary always contains the archetype ("built as a Sharpshooter"), school, record, a stat blurb, the jumper rating and FT%. Verified: with only `summary` ticked, the note includes team, record, archetype and stat data. Unticking `team`, `archetype`, `stats` or `shooting` therefore does not remove that information. Fix: make the summary read the selection, or split it into an opt-in "scouting summary" and a plain "what he is" clause.
* **N4. The Notes tab and the exported file disagree about honors.** With *Export awards* on (the usual case), `exportFile` strips the template's `Honors:` / `Earlier honors:` lines and re-appends them at the **end**, **unabridged** (`js/engine.js:7098-7130`). The Notes tab shows the top 6 plus "(+3 more)", in template position. Verified on one player: tab = 6 honors + "(+3 more)" before *Board*; file = 9 honors after *Board*. Fix: build the honors line once, in `buildNote`, with the export scope applied, and stop post-editing the string.
* **N5. Line order does not follow the template.** The order is fixed by the code order inside `buildNote` (`engine.js:5787-6020`), not by the order the user ticked, and there is no way to reorder. Lines the template calls "Where he finished" (ranks) print before "Season high"; "Profile" prints after "Coach". Fix: either document a fixed order in the picker or add drag-reorder.
* **N6. `includeNotes: false` also drops honors on the Players-file route.** On that route the note is the only place honors survive (`engine.js:7141` deletes `out.note` after the honors were folded in). The dialog does not say so. Fix: warn in the dialog when both are set.

**Low**
* **N7. Leading blank line.** `engine.js:7127`: `out.note += "\nEarlier honors…"` when the note was empty after the `Honors:` strip yields a note that starts with `\n`.

## 3. Settings, solvers, stats, formulas, calculations

### Defects (ordered by impact)
1. **PER pace adjustment ignores game length** — `js/bbgmstats.js:280`: `paceAdj = league.pace / t.pace` compares possessions per game while uPER is per minute. Verified on 6 seeds with non-college destinations: 48-minute clubs get PER ~17 % low, 32-minute prep teams ~25 % high; EWA (derived from PER) follows. Use `(league.pace/leagueMinutes)/(t.pace/gameMinutes)`.
2. **Potential double-counts age** — `engine.js:1557` sets `classAge` from the file's ages (~19) but `phasePot` passes rolled ages (19-24); `ratings.js:1517` `ageClass = clamp((classAge-age)*1.6,±4)` therefore stacks a second absolute age slope. Measured mean term: Sophomore -1.8, Junior -3.3, Senior/Graduate -4.0; class-wide mean -1.99 (should be ~0). Pot is biased ~-1.1 and upperclassmen are over-penalized. Use the mean of the rolled ages, or zero the term when ages are uninformative.
3. **`efficiencyEnv` moves shooting but not scoring**, and the hint (`app.js:1200`) promises "+2.2 team points per game". Measured: ±3 changes TS by -0.025/+0.016 and team points by 0; box possessions drift from scoreboard tempo (+3.1 at -3, -1.4 at +3), so ORtg/DRtg/WS/PER disagree with displayed tempo. Feed the dial into `pointsPerPair` or correct the hint.
4. **Team Win Shares are over-dispersed** — `bbgmstats.js:357` uses the NBA 0.32 constant (~23 pts/win) where the sim implies ~28. Over 1,092 teams, slope of team WS on wins is 1.32; best 60 teams 30.8 wins vs 37.5 WS. Stars on good teams are ~20 % inflated.
5. **`injuryRate` is quadratic and saturates at ~2** (`engine.js:2934-2935`). Injured share: 0.5→8.6 %, 1→31 %, 1.5→61 %, 2→92 %, 2.5→93 %, 3→94 %. The top third of the slider is inert; nothing says doubling the rate quadruples injuries.
6. **`statNoise = 0` is not deterministic** (`engine.js:1461`: `max(0, cfg+N(0,0.25))` → effective 0-0.44) despite the hint "follow ratings exactly". **Pace jitter has no ceiling** (`engine.js:1458, 5058`), so at slider 82 the realized mean is ~81 (one-sided truncation) and the declared band (55-82) differs from the slider floor (58).
7. **Most Improved Player is biased against the class** (`awards.js:237`): the field's improvement is N(0,1) while prospects' is a residual from a fit extrapolated to talent 65-85; prospect mean is -1.13 sd; only ~0.2 MIP awards per class go to prospects.
8. **Flavor bends escape the CLAMP bands** (38 values, e.g. `potSpread` -2.25, `coachTurnover` 212, `freshmanShare` 101); the effective settings box can show illegal values. Two flavors ("chalk year", "one-league dominance") set `midMajorLift` negative, which `teams.js:1171` clamps to 0, so they cannot weaken mid-majors. `bluebloodDownYears` clamps to 8 in `teams.js:1159` but 6 in `CLAMP`.
9. **`potSpread` is mislabeled and near-inert** (realized gap sd 5.57→5.89 for spread 0→10); under `potModel = "bbgm"`, `potBias` and `potSpread` have no effect and are not dimmed.
10. **Label mismatches:** classQuality hint says top prospect "43 + 2.6q" (the pre-boost base; measured post-cap ~53); `transferShare` realized 42/65/83 % at 34/62/90; `redshirtShare` applies to upperclassmen, so 8 gives 5.5 % of the class.
11. **Award "teams of five" are unequal** (`awards.js:1011-1013`): strict 1.5 → 3/4/3 and 2.0 → 3/2/3. Compute the slot count once.
12. **`upsetFactor` 0 is not chalk:** a 10-point favorite still loses 14 % at 0 (19 % at default). Seed results: 8v9 favorite wins 63 % (history ~50 %); 1v16 99 %. `winProb()` is exported but unused.
13. **Smaller:** MPG mean 31.6 vs 30.6 anchor (validate bands hide ~1 mpg); prospect TS premium +0.7 vs stated +3.3; `statLine.drtg` (hand formula) and the export row `drtg` (Oliver) are two numbers for one player; pro-league pace gets `scoringEnv*1.2` against its own comment (`stats.js:2799`); `touchUp` always spends the last point on `stre`.

### Settings audit
* Every slider parsed against `CLAMP`/`sliderRange`: no min/max/step mismatches; defaults sit on their grid; all 53 clamped keys have a control.
* Inert in a single run by design (identical output at both extremes): classQuality, classDepth, eliteCount, rookieOvrCap (curve-only); portalRate, recruitMomentum, coachTurnover, realignmentMemory, extrapolateYears (universe-only); poolMemory, flavorMemory, anomalyMemory, flavorReach.
* Settings with a reduced effective range: injuryRate, pace top, statNoise 0, potSpread, efficiencyEnv, upsetFactor (items 3, 5, 6, 9, 12).

### Checked and correct
BBGM `ovr`/pos/skills constants; hgt↔inches map; the ovr solver (1,500 players × 12 configs × a 714-case edge grid: 0 mismatches, 0 NaN, ratings are integers 0-100, `touchUp` fires in 1.4 % of solves); height lock; class curve and preserve mode (never inflates); TS%, eFG, USG, AST/REB/STL/BLK%, ORtg/DRtg (Oliver), OWS/DWS, BPM 2.0 coefficients, VORP, Game Score, league PER normalization to 15; possession identity; box-score identities (pts = 2fg + tp + ft, zones, min ≤ available); bracket (68 teams, 4 First Four games, S-curve, Final Four pairing #1v#4 and #2v#3, pods); NET and AP logic; RNG (xmur3 + mulberry32, child streams order-independent); determinism and per-player stream isolation; a sweep of all 53 settings at both ends (106 runs): no NaN, no impossible stat, no throw.

## 4. Replayability

### What exists
Seeds and seed history, `variation`, 385 archetypes with a 46-build pool and pool memory, 66 class flavors, 32 anomaly kinds, 12 narratives, `weirdness`, 22 presets, 3 eras, 222 traits; a daily challenge, a 6-tier campaign, a find-the-settings puzzle, share codes, ghost rival, 10 mutators, bingo, 18 achievements, unlocks; the Play tab (predict, bracket pool, blind scout); "Reroll until", batch, Surprise me.

### Measured variety (24-30 seeds, same file, defaults)
* Pools overlap little (mean Jaccard 0.07); 22 distinct flavors in 24 draws; 30 of 32 anomaly kinds seen; 16 distinct champions in 24 seeds.
* **The seed cannot change the class's talent level in the default `preserve` mode.** Top-1 ovr is 55 in all 24 seeds; class mean ovr is 35.41 with sd 0.00; the count of 55+ prospects is exactly 1; age sd 0.03. 18 of 66 flavors (26 % of weight) bend classQuality/classDepth/eliteCount, which do nothing in preserve mode. "Weak year", "loaded" and "no stars" cannot happen by default. With `ovrMode: "curve"` the dial works (top-1 56-63).
* The No. 1 pick came from 5 source players across 12 seeds; top-10 overlap between two seeds is 6.1/10. Same men, reshuffled.
* Text is not the weak point: 256 news kinds, 862 headline shapes in 2,698 headlines, 700/700 notes distinct. Narratives are the thin layer (12 kinds; "attrition season" in 37 % of classes).

### Findings
1. Seed does not change class strength in preserve mode (above).
2. **Dead tiles/achievements at defaults:** strangeness kinds `sleeperNo1`, `starStudded`, `noStars` never fired; `smallTop5` fires in 80 % of runs; achievements `giant-no1`, `nowhere-no1`, `strange-50/70`, `loaded-class`, `all-ones`, `anomaly-six` were not reached. A bingo card averages ~2.25 dead squares, and "Blackout" is ~1 in 220. The 1990s era unlocks only through `strange-70`, which was never reached.
3. **The daily is not the same class for everyone** unless they load the same file: it sets only `seed: "daily-DATE"` and `cfg: {}`; preserve mode keeps the file's ovr, heights and names. The built-in sample is `Date.now() % 100000`, and share codes carry no sample id, so a recipient cannot reproduce it.
4. **Daily content is shallow:** 24 distinct goal sets over 366 days from 7 predicates, always default settings; only 6 static challenges.
5. **Play scoring is farmable:** `saveRecord` increments on every reveal, so replaying a seed after seeing the answers inflates the record. A champion pick scores the same however unlikely. The "Difficulty" label does not track chalk score (899 vs ~750 of 1,920).
6. `flavorBlend` defaults to 0, so flavors are drawn singly.
7. Seeds are opaque base36 strings; batch summaries do not record strangeness, No. 1 pick or anomalies, so you cannot hunt for interesting seeds.

### Ideas
* **Make seeds matter in preserve mode (M, high impact):** a rank-preserving, deflate-only remap of the file's ovrs driven by `classQuality<0`, `eliteCount` and `weirdness`; spend "loaded" through `pot` instead. Hook: `engine.js:1603`, `ratings.js:classCurve`. Gate behind a new setting so goldens hold.
* **Canonical sample + class id in every code (S-M):** deterministic `sample-<id>` classes; put `sm:<id>` in `encodeConfig` and share codes; the daily loads the canonical sample unless you opt into your own file.
* **Themed dailies (S-M):** add a flavor and mutators to the daily from the same date hash; weekday rotation (Mon bracket pool, Wed blind scout, Sat bingo).
* **Fix bingo/achievement reachability (S):** draw cards only from reachable tiles, add a free centre, retune `smallTop5`, re-gate the 1990s era.
* **Seed scanner (M):** run 30-60 seeds in the batch worker and show a card per seed (flavor, strangeness and reasons, No. 1 pick, champion, anomalies); sort by weirdest, weakest, chalkiest; save a named collection.
* **Named seeds ("Warm-Otter-419") (S).**
* **Play progression (M):** dedupe the record per seed (replays are practice), keep a result log and streaks, score picks against implied odds, show the chalk baseline.
* **More axes:** 30 narratives with memory, `flavorBlend` ~0.3 (breaks seed reproducibility; gate with a settings-version bump), era shocks (rule changes), recurring program identities.
* **Universe as the long game (L)** — see §5 for the universe side.
* **Share cards (S):** a one-screen visual class card beside the share code.
* **Challenge variety (S-M):** mirror challenges, "fewest rerolls" speedruns, predict-then-verify.

## 5. Universe mode

### Defects
See §1 items 6-10 and 23-24 for the full list with locations. In short: a throw in the chain loop wedges the universe; note-template changes and player overrides behave differently between the live chain and a rebuild; threads and records count extrapolated seasons as real; fingerprints are too weak to detect an edited class or a diverged replay; persistence fails silently or all-or-nothing; the ETA is wrong.

Additional defects found in this pass:
* **`ENGINE_REV` has never been bumped (it is still 1)** while dozens of commits touched engine, teams, ratings and stats. Nothing ties a golden-hash change to a bump, so an imported universe can replay into a different world with no warning. `resultFingerprint` (`universe.js:82-97`) covers only champion, POY, top-10 board and carousel count; carry changes, standings, Final Four and awards can change unflagged.
* IDB: transaction abort/quota resolve `null`, autosave failures are swallowed, there is no `navigator.storage.persist()`, and slot saves overwrite without confirmation.
* Loading a slot leaves the previous files and results on other tabs; the next setting change can silently replace the loaded world (`app.js:7350`).
* Extending a universe mutates `prior` in place; a throw mid-run leaves the previous world half-rewritten (`universe.js:3071`). Held seasons whose files are not loaded are skipped for recruiting pooling, so an extended world differs from a cold rebuild without a note.
* A failed season leaves no saved config, so resume from it would throw and extend is blocked until a cold rebuild (`universe.js:3101`).

Continuity checks that came back clean: champion row = bracket champion every season; no class player on two teams; no impossible records; coach age and tenure +1 per season; hired-away coaches leave the old school; class-year ladders advance by one (0 anomalies across 360 men); one program row per played season; no thread references a season without a row; conference counts stable over 16 seasons. `node tools/universe.js` gave 134 ok, 0 FAIL.

Calibration note: with thin 30-man classes, a 16-season universe gave one school 8 titles with a 5-peat (carry, prestige and momentum feedback dominate). With 60-man classes the maximum was 3-4. `tools/validate.js` has no universe-level band.

### Improvements (priority order)
* **P0 robustness (S each):** guard `chain.step`/`chain.finish`; make notes and overrides parity tests (rebuild fingerprint equals live); one `played(rows)` helper for threads and records plus a dagger on guessed data; bind `ENGINE_REV` to the goldens and enrich the fingerprint.
* **P1 persistence and speed:**
  * Persist compressed class files in IndexedDB keyed by fingerprint, so real-file universes can resume, extend and open season pages after a reload (today only synthetic worlds rebuild).
  * Restore lazily instead of re-simulating at startup (a 40-season synthetic world costs ~50-70 s per reload).
  * Move the chain into `js/worker.js` (L), or yield between engine phases (S-M).
  * Autosave only when the universe changed.

## 7. Larger features and next steps

### Engineering findings that gate the features
* **The test suite is one serial process with no tiers.** `node tools/test.js` did not finish in 110 s; the 19 area files run as separate processes sum to ~480 s with 0 failures; `validate.js 20` (CI) takes roughly 5-6 min; `tools/universe.js` > 2 min. A suite that takes this long is not run before changes.
* **CI:** `validate.js 20` runs three times (plain, `--baseline`, `--json`); one run could feed all three. No matrix, no cache, no Node 22, no lint, no bench gate; the "Six jobs" comment is stale. `uismoke.js` exits 0 silently when Playwright is missing.
* **No static analysis, no `package.json`** (~76k lines). `ESLint no-undef` ran clean in the bug pass; keep it in CI.
* **`ENGINE_REV` has never been bumped** (see §5).
* **`LEAGUE_DATABASE_VERSION = 73` is hardcoded** (`bbgm.js:21`); read it from the uploaded league and warn when the file is ahead.
* **Script load order is hand-synced in three places** (`index.html`, `worker.js`, `validate.js`). One `js/manifest.json` would feed all three.
* **Error reporting is local only.** A "Copy bug report" with seed, settings hash, `ENGINE_REV` and stack is a full repro for a deterministic engine (~1 day).
* **Versioning is scattered** (`STORE_VERSION`, universe `VERSION`, `ENGINE_REV`, IndexedDB `open(…, 1)` with no upgrade path; slot records carry no schema field).

### Features
* **F1. Real draft simulation (8-12 days).** Today `draftSlot` is the board sorted by `stockScore` plus a shuffle; there are no teams, lottery or needs.
