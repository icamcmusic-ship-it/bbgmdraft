# Full audit — 2026-10-05

Audited at HEAD `5029bbe`. Each section was produced by an independent pass. Passes did not read the earlier `AUDIT-*.md` files or each other's output; sections only point to each other by number (§).

"VERIFIED" means reproduced by running code (Node harness, CLI, or headless Chromium). "UNVERIFIED" means read from source only. Line numbers are approximate. Scratch scripts for every pass were kept outside the repo.

**Headline results**

* **Notes (§0).** The generation half is sound: all 19 template lines, ticked alone or in combination, produce exactly their own line in picker order, and the Notes tab matches the engine. The mismatch you see comes from what surrounds it. Presets silently reset the template (N1), "Include scouting notes" off deletes notes already in the file (N2), the file differs from the Notes tab in six ways despite the "exactly what gets written" wording (N4), awards are listed in the note but have no award rows in game by default (N5), and BBGM does not show `note` in the Draft Scouting table at all (only on the player page, Notes page and Watch List).
* **Bugs (§1).** No High-severity bug. Four Mediums: size rewrite hole (B1), cross-class session restore (B2), missing `tid:-2` (B3), league season read from the wrong field (B4).
* **Calculations (§3).** `ovr`/`pos` are exact against BBGM source (300,000 vectors, 0 mismatches). Real issues are the solver landing on the bottom of the rounding plateau (C1), "Preserve each ovr" silently lowering high-ovr prospects (C2), and pace/preset/label problems.
* **Universe (§5).** The timeline's "player of the year" is often the wrong man (UV1), and a saved universe is unreachable after reload (UV2).
* **Replayability (§4).** Class talent level is fixed by the file in default mode (R1), two mutators are silent no-ops (R2), and sample-class seeds are not portable (R3).

## 0. The notes problem (reported by the user)

**Bottom line.** The generation half is sound. Every one of the 19 line keys, ticked alone or in combination, produces exactly its own line, in picker order, and the page and the engine agree. What breaks is everything around it. Some paths throw away or ignore the user's choice (N1, N2, N3, N7). Other places claim to show "exactly what gets written" and don't (N4, N5, N6, N8). And the game shows notes in fewer places than a user probably expects (see "What BBGM does with `note`").

### What was confirmed to work

* **UI matches engine.** In headless Chromium each of the 19 keys was ticked alone. `state.cfg.noteLines` and the checkbox state matched every time. The Notes-tab text matched a fresh `Engine.run` character for character for every player and key.
* **No leakage, order correct.** 60 random multi-key templates over 60 players (3,600 notes), keys fed in shuffled order: every note equalled the concatenation of the single-key notes in picker order, zero mismatches. `NOTE_LINES` order equals `buildNote` emission order (`engine.js:5786-5813` against `5926-6141`). Only `summary` is context-sensitive, by design.
* **No length cap in this tool.** The "Everything" preset reaches about 2,000 characters per note (longest 2,084).
* **Warm re-runs are correct.** The `notes` phase depends only on `noteLines` and re-runs whenever an earlier phase changed.
* **Persistence works.** Settings survive reload and the `#c=` hash carries `noteLines`. `Config.make` keeps an empty list empty (`config.js:612-616`). The class file itself is not restored after reload; only settings are.
* **Universe mode follows the template** (`universeCfgFor`, `app.js:4824`), and the notes-only shortcut works.
* **CLI works** (`--notes injury|Short|stat`, with `noteBool`; unknown keys error clearly).

### Findings

**N1. Applying any class preset silently resets the note template. Medium-High. VERIFIED (UI).**
Tick "Stats" and "Stock only", then pick any preset ("Weak class" in the run): `state.cfg.noteLines` becomes the 7-line default and the boxes repaint, with no message. Cause: the preset handler (`app.js:3239-3252`) rebuilds `CFG.make(Object.assign({}, p, keep))`; `keep` only protects `SESSION_TOGGLES = ["universe","lockHeights","narrative"]`, and none of the 17 built-in presets contain `noteLines`. A user-saved preset has the same problem because it stores deltas from default. Fix: add `"noteLines"` to `SESSION_TOGGLES`.

**N2. "Include scouting notes" off also deletes notes already in the file, and ignores "Keep any note already in the file". Medium. VERIFIED.**
`engine.js:7288-7291` does `delete out.note; delete out.noteBool` unconditionally. With source note "FILE NOTE zero", both `{includeNotes:false}` and `{includeNotes:false, noteAppend:true}` drop it. A user who wrote notes in BBGM, re-exports, and unticks the box "to keep the file clean" loses them. Fix: when `includeNotes === false`, restore `orig.note` (minus `My notes` and Honors blocks), or relabel to "Remove all notes".

**N3. Whether a source note is replaced or kept depends on whether the template produced text for that player. Medium-Low. VERIFIED.**
`engine.js:7137-7142` only writes `p.note` when non-empty. Template `[]` leaves every source note while the Notes tab says "No notes". With "Injury" alone, 21 of 40 players get the generated note, 18 get nothing, 1 keeps "FILE NOTE zero": a mix of generated and stale text. Fix: treat "template wrote nothing" the same everywhere (clear unless `noteAppend`), or say so in the Notes-tab empty state.

**N4. The tab and sidebar say "exactly what gets written"; the file differs in six ways. Medium. VERIFIED.**
Claim at `views.js:5576` and the `grp-notes` hint. (a) With "Include college awards" and "major honors only", `place()` (`engine.js:7248-7262`) rewrites or removes Honors lines: 41 of 60 notes differed from the tab. (b) `My notes` is appended as a final block (`engine.js:7292-7295`); the tab and copy buttons never show it. (c) `includeNotes:false` removes the note (N2). (d) The Players-file route forces honors into the note (`honorsInNote`, `engine.js:7616`). (e) `noteAppend` stacks the source note above the generated one. (f) The stats-line season label can differ from the exported row (N9). With default toolbar options and no awards scope the file and tab are byte-identical (60 of 60). Fix: build the tab from the same function the export uses ("Preview as exported"), or soften the wording.

**N5. By default the note lists honors but the player has no award rows in game; export choices do not survive reload. Medium. VERIFIED.**
The default template ticks "awards", but the toolbar "Export JSON" uses `currentExportOpts()` = `{ages, injuries, jerseys}` (`app.js:9862`), so `opts.awards` is off: 29 notes had a Honors line and 0 players had an `awards[]` row. `state.exportOpts` is not in the `persist()` payload (`app.js:355-420`), so "Include college awards", "Include my notes" and the scope revert after reload with no indication on the button. Fix: persist `exportOpts`, show a one-line summary on the Export button, or default `awards` on whenever "awards" is in the template.

**N6. The watchlist is dropped on the league-merge route though the dialog says it is written. Medium. VERIFIED.**
The merge `overlay` whitelist (`engine.js:7938`) lacks `watch`. The Players-file route strips it (`PLAYERS_FILE_STRIP`, `engine.js:7610`), which is correct for BBGM's `importPlayers` (it doesn't copy `watch`) but unexplained. Only the class-file route writes `watch:true`. Fix: add `"watch"` to the merge whitelist; say in the dialog which routes carry the star.

**N7. "Keep any note already in the file" does nothing on league merge, and stacks on re-export. Medium. VERIFIED.**
`noteAppend` reads `orig.note` from the class file (`engine.js:7130`); merge overlays the class-file note onto the league's prospect. A league prospect with "LEAGUE NOTE 0" and `{noteAppend:true}` came out as just the generated note. On a re-export round trip each earlier generated note is treated as "the file's own note" and the new one is appended: three rounds gave three stacked, partly contradictory notes ("junior" and "redshirt junior"). Fix: on merge seed `keep` from `target.note`; store a marker (as My notes does) and strip the previous generated block before appending.

**N8. After changing the template, tooltips and an open player page keep showing the old note. Medium-Low. VERIFIED (UI).**
`app.js:5310-5328` skips `render()` when only the notes phase ran and the tab isn't "notes", on the comment "the note text is only ever shown on the Notes tab". The note is also the Draft-board row tooltip (`views.js:1669-1671`), the "Scouting note" block on the player page (`views.js:6370`), and site/almanac exports. Repro: open a player page, click "None": `p.note` is `""` but the page still shows the old text. Fix: remove the skip.

**N9. Season label mismatch when `draft.year` differs from `startingSeason`. Medium-Low. VERIFIED.**
A class with `startingSeason` 2026 and `draft.year` 2027 gives a note line "2026: 21 GP…" while exported stat rows are labelled 2026 and 2027. `buildNote` prints `state.season` (`engine.js:6019`); `exportFile` shifts seasons by `seasonShift` (`engine.js:7326`). "Earlier honors: 2025 …" becomes "2026 …" if "Include college awards" is ticked, so the same note changes with an unrelated checkbox. Fix: pass `exportSeason` to `buildNote`, or have `exportFile` rewrite the labels.

**N10. A ticked line can legitimately print nothing, and the picker never says so. Low-Medium. VERIFIED.**
Over 150 players (126 college, 24 abroad): `ranks` prints for about a third (never abroad, `!p.nonNcaa`, `engine.js:6043`); `injury` for about half of college players and none abroad; `coach` never abroad; `awards` absent for about a third; `path` absent for 6 of 24 abroad. Ticking only one such line leaves many players with no note and (with N3) a stale source note. Fix: annotate labels and show "n of N players will get this line" next to each checkbox.

**N11. The "Postseason" line contradicts "no postseason". Low. VERIFIED.**
89 of 480 players on a team whose record line ends "· no postseason" (`engine.js:6001`) also get "Postseason: 2 games…" from `march`. `postseasonSplit` (`stats.js:4664`) counts any non-"reg" stage, including conference-tournament games. Fix: relabel or restrict to NCAA/NIT stages.

**N12. League merge: the note can disagree with the league's own player. Low. VERIFIED, conditional.**
On merge `hgt`, `weight`, `born` come from the league unless this export rewrote them (`engine.js:7938-7960`) while the note's size and class year come from the simulation. With a league listing 79" and the class built at 7'0", the note said 7'0" in 29 of 30 notes. Only bites when height was edited in game. Also on merge `noteBool` is deleted when the league's own note is kept (`engine.js:7942`); harmless, BBGM re-derives it.

**N13. The Almanac prints Honors twice with different scope. Low. VERIFIED.**
With "awards" in the template the capsule prints its own `**Honors:**` (full scoped list) and then the note's "Honors: … (+19 more)" (`almanac.js:430-437`).

**N14. The three copy actions and two exports don't match the cards. Low. VERIFIED by code.**
Cards skip empty notes (`views.js:5625`); "Copy all notes", the spreadsheet rows, the Markdown copy and `notes.tsv`/`notes.md` emit blank entries (`views.js:5595-5612`, `app.js:9505`, `9531`). None include My notes.

**N15. CLI gaps. Low.** No `includeNotes`, `myMarks` or `noteAppend` flags (`bin/bbgmdraft.js` `exportOptions`); preset names differ from the page (`stat` vs "Stat sheet", `all` vs "Everything").

**N16. Wording and labels. Low.** The third summary variant opens as a fragment ("Put up 28.6 points … as a 6'11" freshman forward"); `highs` starts lowercase; "School / club, conference, class year" also writes team style and "first year after leaving…"; "Archetype label" appends ", left-handed"; "Honors" writes two lines; "mock: round 1, pick 12" and "No. N" are the tool's own board, not BBGM's draft order or rank (BBGM's own scouting rank was not verified); the "Note template" group is collapsed by default and presets show no active state.

### What BBGM does with `note`

Read from a fresh clone of zengm at `bed6816b` (2026-10-04).

**Confirmed from source**
* **Draft → Import preserves `note`.** `handleUploadedDraftClass` (`src/worker/api/index.ts:2563`) only deletes `p.stats` and a few counters, then calls `augmentPartialPlayer`, which sets `noteBool = 1` when `p.note` is truthy and deletes an empty `note` (`augmentPartialPlayer.ts:442-446`). It normalises `watch: true` to `1` (lines 434-440), so `watch` survives a class import.
* **Tools → Import players** copies `note` and `noteBool` only `if (p.noteBool)` (`api/index.ts:2777-2780`) and does not copy `watch`. Our `noteBool = 1` is required on that route.
* **League files** go through `processPlayerNewLeague` → `augmentPartialPlayer`, keeping `note` and `watch`.
* **Display.** `src/ui/views/Player/Note.tsx` renders the note in a div with `whiteSpace: "pre-line"`, `maxHeight: 300`, `maxWidth: 600`, as a React text node: newlines and blank lines survive, nothing is HTML-parsed. No length cap in the component, textarea or `setNote` (`api/index.ts:3900-3925`); a 2,000-character note scrolls inside the 300px box. Shown on the player page (`Player/TopStuff.tsx:752`), the Notes page (`/notes/player`) and the Watch List column (`WatchList.tsx:186-200`).
* **Not shown** in `DraftScouting/DraftClass.tsx` or `views/draftScouting.ts`: only the watch star appears in the Draft Scouting table. A user scanning the draft table sees none of the ticked lines.
* **`watch` is numeric** (a colour index 1..`numWatchColors`); `true` is accepted and converted to 1.

**Could not confirm:** BBGM's own draft-scouting rank (to compare with "Board: No. N"); how `draft.year`/`startingSeason` shifts interact with the stats-row label (N9 is internal to this repo).

## 1. Bugs

No High-severity bug was found. Engine, config, export and persistence layers held up under heavy abuse.

**Probed and clean:** warm vs cold runner for 64 numeric/boolean settings plus choice settings; `Config.make` idempotent and finite for 1,368 key × garbage-value combinations; about 100 fuzzed configs/files with no NaN/Infinity, ratings in range and matching the BBGM formulas, stat identities holding, duplicate/missing/string pids handled; input never mutated; builders (almanac, site, news, mock, merge, fragment) did not throw; HTML escaping of hostile names; share-code round-trip; localStorage corruption (47 keys × 9 mutations); service worker offline; gzip/BOM/bad-file loading; page-vs-CLI parity apart from B9; reroll during a universe run; about 1,000 random UI interactions with no page errors.

### Medium

**B1. With `lockHeights` off, the "physical outlier" anomaly changes the sim size but not the exported size. VERIFIED.**
`js/engine.js:7010` (`const sized = result.cfg.varySize || …`), anomaly at `1882-1892`. `Engine.run(sample70, Config.make({seed:"hg", lockHeights:false}))` then `exportFile(res, {})`: prospect 26 is listed at 81" and 215 lb, his exported `ratings[0].hgt` is 0, his note says "5'6" freshman point guard", sim weight 173. `exportFile` writes `hgt`/`weight` back only when `varySize` is on or an override was set. The anomaly draws absolute heights (66-68" or 87-89"), not "half a foot" as its comment says: over 14 classes the three outliers shifted −9 to −15 inches. `mergeIntoLeague` has the same hole (`sizeRewritten` uses the same condition). Fix: treat `p.newHgtInches !== p.hgtInches` or changed weight as a rewrite; draw the anomaly relative to the player's own height.

**B2. "Recent classes" restore applies a session saved on another class: its locks and seed go onto whatever class is active. VERIFIED.**
`restoreSession`, `app.js:5453`; `applySnapshot`/`setSnapshot` (`~5330`) never call `checkLockFingerprint`, and sessions are not cleared when files are replaced. Lock pid 0 at ovr 70 on class A, load class B, call `App.restoreSession(0)`: `state.overrides` becomes `{"0":{ovr:70}}` and B's pid 0 (Tyrese Whitmore) is forced from 47 to 70 with the status "Returned to: The 2026 class" and no warning. This is the failure the lock fingerprint exists to prevent, and the wrong-class overrides are persisted. Fix: store the file fingerprint on each session; on restore switch to that file or refuse, otherwise drop foreign overrides with a warning.

**B3. A class whose players have no `draft.year` exports without `tid: -2`, which BBGM's Draft → Import silently drops. VERIFIED.**
`engine.js:7370`: the tid repair runs only `if (Number(out.draft.year) === Number(exportSeason))`. A 20-player class with `draft: null` and no `tid` exports `tid: undefined` and `draft` of only `{ovr, pot, skills}`; the code's own comment names this failure ("imported as ZERO players, with no error on either side"). `findSeason` and `validateLeagueFile` accept such files. `exportPlayersFile` repairs a missing tid (`~7620`), `exportFile` does not. Fix: for a non-league class file always set `tid = -2` and fill `draft.year = exportSeason`, `round = 0`, `pick = 0`, `tid = -1`, `originalTid = -1` when absent.

**B4. For league exports `findSeason` reads top-level `startingSeason`, but `gameAttributes.season` is the current season.**
`engine.js:525` prefers `lf.startingSeason`, then `lf.season`, then `gameAttributes`. VERIFIED in code: a league with `startingSeason: 2020` and `gameAttributes.season: 2026` returns 2020. UNVERIFIED that real BBGM exports put the founding year in top-level `startingSeason` (believed so; repo fixtures always set the two equal). Effect: `mergeIntoLeague` skips the "that draft has already happened" warning (`engine.js:8072`; merging a 2024 class into a 2026 league gives `warnings: []`), and the oversized-league `classPids` fallback in `classesFromFile` and `Universe.validate` offers the founding-year class. Fix: for league-shaped files prefer `gameAttributes.season`.

### Low

**B5. Class-file export keeps stale `value`, `valueFuzz`, `valueNoPot`, `valueNoPotFuzz` and `contract`. VERIFIED that they are kept; effect in BBGM UNVERIFIED.**
Input with `value: 40…` run with `ovrMode:"curve", classQuality:3` changes ratings (ovr 49→51, pot 67→65) but still exports `value: 40, valueFuzz: 41, valueNoPot: 39, valueNoPotFuzz: 38` and the old rookie `contract`. `exportPlayersFile` strips these (`PLAYERS_FILE_STRIP`, `engine.js:7609`); the class and merge routes do not. If BBGM doesn't recompute them, AI draft order and trade value follow the old ratings. Fix: delete them (and `contract`) on rewritten players.

**B6. Re-importing the tool's own output inflates potential generation after generation. VERIFIED.**
100-player class, same seed, each export fed back as the next input: mean pot−ovr gap 11.0, 11.0, 11.5, 12.2, 13.1, 14.2 over six generations (new seeds give the same drift); mean ovr stays 35.8. Cause: `phasePot` (`engine.js:3970`) builds `gap = p.baseGap + bias + factors.total*0.55 + noise` from the file's own gap and `factors.total` is positive on average; the college season is simulated off that gap, so the factor feeds back. Fix: centre the additive factors on zero, or stamp and detect the tool's own output.

**B7. CLI `batch -n abc` runs zero classes and exits 0. VERIFIED.** `bin/bbgmdraft.js:228`: `Math.max(1, Math.round(Number("abc")))` is NaN; empty table, empty CSV, "mean over NaN". Non-numeric should exit 1.

**B8. CLI input errors are silent or misleading. VERIFIED.** `--year abc` → "No NaN draft class" (`bin/bbgmdraft.js:98`); `--set ovrMode=curv` or `collegeSource=bogus` exits 0 with output identical to default (`Config.make` resets invalid choices; `coerce` validates only numbers/booleans); `--set classQuality=99` silently clamps to 3; `check` on a multi-class league errors instead of listing classes; `--year` on a plain class file is ignored. Fix: validate against `CHOICES`/`sliderRange` and report clamps.

**B9. CLI output omits `face`, so CLI and page produce different class files. VERIFIED.** `engine.js:7406`: `Faces` is page-only (`manifest.js`) and `opts.faces !== false && global.Faces` skips it in Node. Every page player has a `face`, no CLI player does, contradicting the CLI header ("a class made here is the class the page makes"). Fix: load `faces.js` in Node or document/flag the difference.

**B10. A source `jerseyNumber` of `""` or `null` counts as "already has number 0". VERIFIED.** `engine.js:7101` uses `Number.isFinite(Number(orig.jerseyNumber))`, true for `""`/`null`; the loop at `~6948` also adds 0 to `jerseysTaken`. `""→""` ×12, `null→null` ×6; stats rows carry the blank. Fix: use the `num()` helper.

**B11. Switching files with `#fileSelect` keeps editing and selection state from the previous class. VERIFIED for the editor.** Handler at `app.js:4615` sets `state.active`, runs `checkLockFingerprint`, `ensureResult`, `render`, but not `state.editing`, `selected`, `player`, `compare`, `logPlayer` (`installFiles` resets them). The editor stays open on key "2", now a different man. Bulk selection and the open player page carry over by pid the same way (UNVERIFIED for those two).

**B12. An override `name` that is an object becomes the literal "[object Object]". VERIFIED at engine level.** `engine.js:1621` `String(ov.name).trim()`, same at export `~6997`; `{name:{x:1}}` gives `firstName: "[object"`. Reachable via a crafted `#c=` link (`readHash` copies `payload.overrides` verbatim; link route not run). A 5,000-character name is also accepted. Fix: strings only, cap length.

### Notes (no action needed)

* `rememberSession` stores `Object.keys(diffConfigs(...))` as `changed`, but `diffConfigs` returns an array, so these are indices; only `.length` is used today.
* `classYear(age)` maps every age of 22 or more to "Senior".
* `fileFingerprint` ignores ratings (see §5 UV17); `universePlayersFile` same-name merge (see §5 UV3).

## 3. Settings, solvers, stats, formulas, calculation

Everything below was run, not read. The network was open, so the real zengm sources (`ovr.basketball.ts`, `pos.basketball.ts`, `potEstimator.ts`, `develop.ts`, `heightToRating.ts`, `limitRating.ts`, `genFuzz.ts`, `fuzzRating.ts`, `compositeRating.ts`, `constants.basketball.ts`, `advStats.basketball.ts`) were fetched from master.

### Checked and correct (VERIFIED)

* **ovr and pos formulas:** the real `ovr.ts`/`pos.ts` vs `BB.ovr`/`BB.pos` on 300,000 random rating vectors: 0 mismatches (coefficients, 48.5 intercept, fudge pieces >=68 → +8, >=50, >=42, >=31, else −10, rounding, 0-100 clamp).
* **Skills and constants:** `COMPOSITE_WEIGHTS` and every skill cutoff identical to upstream; skills sort and `fuzzRating` match; `LEAGUE_DATABASE_VERSION` 73 matches.
* **Height map:** 66-93 inches onto 0-100 matches `heightToRating`; BBGM floors, the tool rounds the inverse, round-trip error ≤2 rating points (immaterial; heights locked by default).
* **potEstimator** (`potModel:"bbgm"`): coefficients exact (72.314, −2.3306, 0.83309; age ≥29 returns ovr; ovr>pot returns ovr). See C12.
* **Solver:** 141,372 players across 77 archetypes, 9 heights, targets 1-100, spec 0-2.5, noise 0-14: 0 misses where the target was inside `ovrRange`; 0 NaN; 0 `pot<ovr`.
* **Engine level:** 1,890 prospects across 9 configs: `newOvr` equals `origOvr` wherever reachable (316 were not; see C2); `BB.ovr(exported ratings)` equals exported ovr; integer ratings 0-100; pot ≥ ovr. Class mean ovr delta 0.000 at every setting tried.
* **Ratings isolation:** college, destination and season settings don't alter `newRatings`.
* **Stat identities** (3,045 rows, 7 configs): pts = 2fg + tp + ft; fg ≤ fga; tp ≤ fg, tp ≤ tpa; ft ≤ fta; shot-zone splits sum to fg/fga; min ≤ minAvailable; gs ≤ gp; no non-finite values.
* **Team conservation** (364 teams): player minutes×gp = team minutes; points, rebounds, assists, steals, blocks and turnovers each sum to the team box (ratio 1.0000).
* **Advanced stats:** PER, EWA, on/off, usage/rebound/assist/steal/block % are line-for-line ports of `advStats.basketball.ts`. BPM and win shares contain no literal absent from upstream but were not diffed line by line (UNVERIFIED).
* **NaN safety** under all-min, all-max, curve, bbgm and 1990s configs at 3 and 70 players.
* **Staging:** 68 settings pushed to max: cached `createRunner` re-run byte-identical to a fresh run.
* **RNG** (`rng.js`, xmur3 → mulberry32): uniform chi² 87.9 on 99 df, normal kurtosis 3.011, `int(0,2)` 33.35/33.35/33.30, sibling-stream correlation 0.0003, adjacent-seed first-draw correlation −0.001, 200k seeds → 200k distinct start states. Seed is 32-bit.
* **Presets and defaults:** every preset key exists and is in range; every default is inside its slider range. `tools/validate.js 3` 362/362; `run-area ratings` 22/22 (full suite not completed).
* **Universe-only settings** (`portalRate`, `recruitMomentum`, `realignmentMemory`, `coachTurnover`, `starReturners`, `extrapolateYears`) each changed a chained 3-season run.

### Defects

**C1. The solver lands on the bottom edge of the ovr rounding plateau. Medium-low. VERIFIED.** `solveToOvr` (`ratings.js:3388-3446`) bisects for the smallest k with ovr ≥ target and keeps `shift(hi)`, the plateau's left edge, so the unrounded ovr lands at target − 0.5. Over 700 prospects it sits at −0.5 for 83-100% (mean unrounded delta −0.42 at defaults; −0.24 at spec 0/noise 0). Every rebuilt prospect is ~0.4 ovr weaker underneath than a centred solve; at spec 0/noise 0 about 27% move one rating point on many ratings. `touchUp` (`ratings.js:3276`) fires 0-2% and only moves up, preferring early keys (observed 12 stre, 5 spd, 1 oiq). Fix: find both plateau edges and return the midpoint.

**C2. "Preserve each ovr" silently lowers high-ovr prospects. Medium. VERIFIED.** Default rookie skill and physical caps (70, 80) limit reachable ovr: a file ovr of 84-95 at hgt 50 becomes 83. Reach under defaults is 75 at hgt 0, 83 at 50, 89 at 90, 91 at 100 (94-100 with caps off). `res.warnings` is empty; `lockUnreachable` (`engine.js:1758`) fires only for locked/pinned players. The `rookieOvrCap` hint says preserved overalls are kept, true only for the ovr cap. Fix: warn whenever `built.ovr !== targetOvr`, or exempt preserve mode from the caps.

**C3. Default rookie caps rewrite strong prospects' ratings even at specialization 0. Medium-low. VERIFIED.** With spec 0, noise 0, diversity 0, an ovr-72 prospect (spd 95, jmp 92, dnk 85, tp 85) came out spd 83, jmp 82, dnk 73, tp 73 while oiq, diq, ins, reb each rose 7. With caps off he is unchanged. "Specialization 0 = BBGM's samey builds" and "only his build changes" don't cover this.

**C4. A setting sitting at its default cannot be pinned against storylines, flavors or weirdness. Medium-low. VERIFIED.** `applyNarrative` decides "touched" with `userCfg[k] !== D[k]` (`engine.js:~1297`; same pattern in flavor and weirdness). Pace slider 68 (default) gives effective pace sd 3.8 vs 2.7 at 67 or 69; sweeping 66/68/70 with a storyline gave 69.9/75.9/73.9 possessions and slider 68 equalled 72. Fix: track touched keys explicitly.

**C5. Pace is mislabeled and saturates. Medium-low. VERIFIED.** "Pace (poss/40)" with storylines off realises 61.1 at 58, 71.2 at 68, 75.3 at 72, 81.7 at 80 and 82; 80 and 82 are identical because jitter, `scoringEnv`×1.6 and style are clamped at 82 (`engine.js:1499`, `stats.js:2800`). Default league is 75.2 points on 59.5 FGA vs the modern anchor 73.6 / 57.5 (+2% / +3.5%). Storylines swing league scoring ±10 ppg (`validate.js` 66.8-86.3 vs a [58, 92] band). Fix: jitter before the clamp or widen the band; relabel the unit.

**C6. Steals, blocks and fouls don't respond to pace. Low. VERIFIED.** Team stl/blk/pf have the same range at pace 58 and 82; correlation with possessions 0.05/0.01/−0.02 vs 0.65-0.80 for turnovers. League blocks 3.9 vs 3.5 anchor (+11%), steals 6.6 vs 6.3 (+5%). Fix: scale by opponent possessions.

**C7. `efficiencyEnv` is narrow, asymmetric and keeps team points fixed. Low. VERIFIED.** At ±3: TS% +1.2/−2.0 points; offensive rating +2.0%/−3.4%; team points stay 82.68/82.65 while possessions move (74.4 at +3, 78.7 at −3), so "everything falls" means fewer possessions.

**C8. Prior-season stat rows export zero advanced stats beside real totals. Low. VERIFIED.** With `priorSeasons="reconstruct"`, 316/316 prior rows have per, ortg, drtg, usgp, ows, dws, obpm, vorp, ewa all 0 (deliberate per the comment at `engine.js:~6735`). With "simulate" (default) 33 of 316 (10%) have the same zeros (e.g. gp 33, 462 min, 156 FGA but PER 0). BBGM tables will show PER 0 for players with real minutes. Fix: omit/null the fields, or compute against a field-average team.

**C9. Many calibration bands cannot fail. Low-medium. VERIFIED.** Of 362 checks, 58 have a negative lower edge on a non-negative stat ("25+ PPG scorers/class [−2.11, 6.41]"); 79 span more than 2.5× ("MPG p5 [3.93, 40.07]", "PF mean [0.16, 4.54]"). "All checks passed" overstates how well the model is pinned (`validate.js`, `calibration.js`). Fix: derive bands from sampling sd, floor at 0, cap width.

**C10. "Exactly N% stay Balanced" is not exact. Low. VERIFIED.** At diversity 85 the Balanced share was 13.3% (per class 2-14 of 70); at 100, 0%; at 50, 49.1%; at 0, 93.6% (so 4-6 players per class aren't Balanced even though the hint, `app.js:~1131`, says "every single player is Balanced"). **C11. Two presets over-promise. Medium-low. VERIFIED.** "Guard-heavy class" is `{classFlavor:2, archetypeDiversity:92}`, which only strengthens a random flavor: 12 seeds drew 12 different flavors, "guard-heavy" once. Fix: `flavorHint:"guard-heavy"`. "International class" sets only `leagueWeights`, which apply to blank colleges: non-NCAA share 16.7% under both default and preset (19.6% with `collegeSource:"rewrite"`). The weights are a hard-coded snapshot that can go stale.

**C12. Potential labels and units. Low. VERIFIED against fetched source.** The `potModel` label "BBGM potEstimator (what the game will show)" (`index.html:148`) overstates: `develop.ts` uses `monteCarloPot` and takes the estimator only when `usePotEstimator` is set or the league has ≥ `TOO_MANY_TEAMS_TOO_SLOW` teams; the real estimator adds randInt(−2,2), the tool's is noise-free. The comment `potSpread: 6, // sd of the ovr -> pot gap` (`config.js`) is wrong (the UI hint is right). Measured gap sd 5.81 at spread 0, 5.94 at 6, 7.19 at 16; 2.9 under the estimator. `potBias −3` gives mean gap 5.7 (hint −6.6: floor at ovr+1 binds), `+3` gives 17.2 (hint +6.6). Curve mode: mean gap 16.4 (tool) vs 19.0 (bbgm); the tool's gap rises with ovr (15.8→18.6), bbgm's falls (20.0→17.0); tool enforces pot ≥ ovr+1, the estimator pot ≥ ovr.

**C13. Inert controls look live. Low. VERIFIED.** `rookieOvrCap` has no `data-curve` (`index.html:183`) so it isn't dimmed in preserve mode where it does nothing; `poolMemory`, `flavorMemory`, `anomalyMemory` do nothing headless (CLI never supplies the rings); CLI `--set` for null-default settings (`leagueWeights`, `wEuroLeague`…) takes the raw string and is silently ignored (`bin/bbgmdraft.js coerce`).

**C14. Output depends on file order when overalls tie. Low. VERIFIED.** Shuffling player order changed 7 of 70 players (37 tied adjacent `origOvr` pairs); ties feed anti-repeat counts in the board loop (`engine.js:~1640`). Fix: break ties by pid/key.

**C15. `varySize` only moves weight under the default `lockHeights`. Low. VERIFIED.** With defaults 0 heights and 65 weights changed; the label says "height & weight".

**C16. Age mix differs from BBGM's. Informational. VERIFIED against `genPlayersWithoutSaving`.** Real classes use `draftAges` [19, 22], 19/20/21/22 about 50/25/12.5/12.5. The tool exports 29/28/19/19/4% at 19-23; the 4% aged 23+ is outside anything BBGM generates. This is the class-year design; the `freshmanShare` note about "real classes" is a college statistic.

### Findings

**R1. In default mode the class's talent level is fixed by the file.** Top and mean overall have sd 0.00 across seeds; variety comes from potential (sd ~3), rebuilt archetypes and which man the board puts first. On a file with one clear best player (D), a re-roll gives the same No.1 90% of the time. The levers that would vary talent do nothing unless the user finds `ovrMode: curve`.

**R2. Two mutators are silent no-ops.** "Loaded class" and "Down year" (`replaymeta.js`) set `classQuality`/`eliteCount` without `ovrMode:"curve"`. The presets "Deep, no stars" and "Blue-blood freshman wave" already set it for this reason. Stacking "Loaded + Down year" returns the unmodified class under a label saying otherwise.

**R3. Seeds and challenges are not portable.** `loadSample()` seeds the sample class with `Date.now() % 100000` (`app.js ~4244`); only the filename carries it, not the link or `BB1-` code, so a link/code/"today's class" made on the sample opens a different class for everyone else. `encodeConfig` writes the file fingerprint (`fp`) only when locks exist, so a link opened against the wrong file silently shows a different class. Scores and bests are not comparable between players.

**R4. The daily challenge is often trivial or unwinnable by the intended route.** Goals depend on the loaded file (`tallTop5` is impossible without a 7'2" prospect, and heights are locked by default); 4/42 pairs score `100 + 10 × budget` for doing nothing; only 12/42 are solved by lever + variations. `tools/tests/replaychallenge.js` checks 3 dates on one fixture. No streak counter, calendar of past dailies or daily-keyed history; personal best is a flat per-key map (`BEST_KEY`).

**R5. The season layer has a fixed amount of "event".** Always 2-3 storylines and 3-5 anomalies; no quiet or chaos year without hand-turning `surpriseBudget`/`weirdness`. Flavor, storylines and anomaly kinds are keyed to the seed alone, so a new file under the same seed gets the same story shapes.

**R6. Text pools are thin where players read most.** Quotes exhaust by about the 15th class; headlines are 11% new at class 20; trait clauses recur heavily. Anti-repeat machinery (`poolMemory`, `flavorMemory`, `recentPools`, `recentFlavors`, `anomalyMemory`) covers builds, flavors and anomalies but not quotes, headlines or trait clauses.

**R6b. Flavor is seed-bound and can't be steered by levers.** Only `classFlavor`, `flavorBlend`, `flavorHint` change it; settings like `injuryRate` and `transferShare` reshuffle champions/No.1 picks 13-75% of the time without changing the class's identity, so moving one is effectively another re-roll.

**R7. The Play tab rewards re-running the same seed.** `saveRecord(kind, points, max, seed)` has no per-seed dedupe: after a reveal the user can press Start again with the answers known and the points count. Scores aren't normalized (no "chalk would have scored X" baseline; difficulty comes from the upset factor the user may have set). No daily-locked Play seed and no shareable Play result code.

**R8. Progression is thin and farmable.** `replayAfterRun` awards achievements on any run, including "Reroll until strangeness:70", which satisfies "Twilight zone" and unlocks the 1990s era in one search. Gated content is 3 flavors and 1 era, with a "show everything" toggle one click away. Ledger, bingo and campaign progress live only in `localStorage`; no export, profile or streak. The collectible space (66 flavors, 12 storylines, 32 anomaly kinds, 385 builds, 227 traits) is never surfaced.

**R9. Seed UX.** Seeds are 6-7 char base-36 strings (`mintRandomSeed`); the link is JSON in the hash and `readHash` accepts only `#c=`, so a friend can't type one. `variation` needs a slider drag; no "next variation" or "same story, new players"; no run-vs-run headline diff.

**R10. The CLI can't measure or drive replayability.** `batch` prints ovr, ppg and champion only (not No.1, POY, storylines, anomalies); no `daily`, `challenge`, `solve`, `diversity`; no CI variety gate.

### Ideas, ranked by value / effort

* **I1. Fix the dead levers (high / trivial).** Add `ovrMode:"curve"` to the "loaded" and "down-year" patches; add a test that every mutator, preset and challenge `cfg` moves at least one headline metric over a small seed set; lint `Config.DEFAULTS` for settings with zero measured effect.

## 5. Improving Universe mode

Method: chains of 1, 2, 3, 5, 6, 8, 12, 14, 20 and 25 seasons in Node (`Universe.beginChain`, the `bbgmdraft universe` CLI, synthetic and gap files); Universe tab in headless Chromium for 6- and 30-season synthetic worlds and a three-file world with a gap, then reloaded. Not exercised: Re-run from a season, Dynasty goal, Follow a program, import-replay divergence. Timings are from a loaded 4-core box.

**What held up:** deterministic replay (including reversed file order); a season rebuilt from `u.cfgs` matches the original exactly (all player lines and team records, 8 seasons); class years monotonic with ≤5 collegiate seasons per man across 719 registry entries; program level lag-1 autocorrelation ≈0.88; 364 teams and 32 conferences constant; W equals L league-wide.

### Defects

**UV1. The timeline's "player of the year" is often the wrong man. High. VERIFIED.** `summarize` (`universe.js ~837`) and `alumniOf` (`~813`) take the first `res.players` entry holding any of seven national POY trophies, and different men often hold different trophies. In a 10-season run, 2027's POY was a man holding only AP while another held six trophies including Consensus POY and Naismith; 2031 likewise. In a 20-season run 4 of 20 seasons had two or three "players of the year" in `alumni`. Downstream: Hall of Fame lists both men (2042); `poyNotNo1` (`universe.js:1705`) says "5 of 8 players of the year" in a 6-season world; `poyAndNo1` says "11 men" while `sweepNamed` lists 12; the Hall's size and the decade player are skewed. Fix: use the Consensus trophy holder or the man with the most trophies; demote the rest.

**UV2. A saved universe is unreachable after reload. High. VERIFIED.** Three real-shaped files, run, reload: `state.universe.rows` held 11 rows from a 255 KB localStorage payload plus the IndexedDB autosave, but the page showed only "Choose a file (or drop it here)": no Universe tab, empty `#view`. Files aren't persisted (`state.files` is 0) so the empty screen wins. The user must re-drop every class file or know to drop an export JSON. Fix: if `universe.rows.length` and no files are loaded, show the Universe tab view-only with a "load files to rebuild" notice.

**UV3. The players file merges different people who share a name and birth year. Medium-high. VERIFIED.** `Engine.universePlayersFile` (`engine.js ~7679`) keys on `first|last|born.year`; later rows replace earlier ones. In a 12-season synthetic world all 14 merges were different men (e.g. Darius Lawson 2010, Duquesne 2028 vs Houston Christian 2029), reported as "14 duplicate men merged"; the earlier man's draft row, stats and awards are lost. Real-file universes with common names are exposed too. Fix: key on the registry `playerId` (plus `college` and `draft.year` for returner re-entries).

**UV4. Synthetic worlds are full of duplicate names. Medium. VERIFIED.** Name pools are ~50 × 44; a 20-season world had 83 duplicate names among 719 multi-season entries ("Ethan Wembanyama" ×3, "Devin Jokic" ×3). The Hall, Careers and news name men ambiguously and some names are real players. This is the zero-file entry path. Fix: de-duplicate across the chain (retry or suffix), widen pools, extend `REAL_NAMES`.

**UV5. Extrapolated seasons go empty after the first missing year. Medium. VERIFIED.** `returnerPool` reads only carried returners and `ageCarry` drops Seniors. With 3 real files then 12 or 30 guessed years: 2028 had a POY and 5 All-Americans; every later guessed year had `poy: null`, `allAmerica: 0`, `no1: null`. A gap ≥4 years or `extrapolateYears` ≥3 produces rows with only champion, runner-up and AP No. 1; the Final Four is just those two teams; no coach changes or realignment. Fix: draw named stars from a synthetic generator seeded by season; add `finalFour`, `no1` and coach-change estimates.

**UV6. Extrapolated champions are flatter than simulated ones. Medium. VERIFIED.** `contendersOf` draws from the top 40 programs with weight (level−40)^2.2 while `ageCarry` regresses levels 18%/year toward the mean. Over 30 guessed years: 23 distinct champions, max 2 titles per team, median champion ranked #28 by level; simulated 20 seasons gave North Carolina 5 titles and Kentucky 3, and mid-level teams win guessed titles. `creditGuess`'s "ten years can produce a dynasty" is false at +2.5 vs 18% regression. Records (`universe.js:2108-2142`) count guessed titles but not guessed title games, so a program can show more titles than title games.

**UV7. Gap length is not bounded. Low. VERIFIED.** A 2025 file plus a 2525 file produced 499 extrapolated rows with no warning or cap; a typo 2205 for 2025 yields 180 phantom rows; `validate` accepts it. Fix: warn above ~15 missing years and cap the guess.

**UV8. Team trophies are counted as personal "honors". Medium. VERIFIED.** Registry honors include "MEAC Regular-Season Champion", "MEAC Tournament Champion", "NCAA National Runner-Up", "Academic All-American". A man is "honoured 15 times" in `cameBack`; "most honors" has a man at 42 (over 5 seasons) and another at 31 (over 2). Fix: individual awards only, or split team and individual counts.

**UV9. Thread text contradicts the data it summarizes. Low-medium. VERIFIED.** `firstTitle` says "8 programmes won a first title… A, B, C and D" but lists 4 (`slice(0,4)`, `universe.js:1294`) with no "and 4 more"; "Won a first title inside this timeline" fires for Kentucky or Duke; `bestRecord … the most` ignores ties (two 41-0 teams both got the thread); `serialMover` says "Bowling Green changed conference 4 times (2031, 2033, 2035, 2035)": a double hop in one realignment pass (Tulsa 2039 too).

**UV10. The "underclassman award" story is wrong for returners. Low. VERIFIED.** The `futureClass` filter (`news.js:3789`) also matches undrafted returners: "Third Team All-American goes to a senior: Marcus Okafor, a senior who will not be eligible until 2028", a man in the past 2028 class. Fix: require `!fp.past` or rewrite for returners.

**UV11. "Program on the rise" reports rating noise as strength. Low. VERIFIED.** `teams.js:938` blends the level as 0.62·fresh + 0.38·carry. p90 year-over-year change +10.8, p99 +20.2; 50 teams in 14 seasons jumped ≥20 (Mercer 14.0→43.5 "about 30 points… not one recruiting class doing it"). Cellar programs teleport and the story text is false. Fix: lower the fresh-draw weight for carried programs or clamp the story to roster causes.

**UV12. Realignment geography is arbitrary. Low-medium. VERIFIED.** Detroit Mercy, Tennessee State, Western Kentucky, Bradley and Long Beach State to the Pac-12; Washington State and DePaul to the SEC; Big East oscillates 16-18 for years; the four big conferences all end at 18. Combine with the double-hop (UV9).

**UV13. Real-world performance and memory. VERIFIED.** `beginChain` runs a synchronous pass-one `previewClass` per file before first render (~0.3 s/file in Node, 13 s for 40 files; longest Chromium stall in a 30-season run 3.6 s then 1.5-1.8 s). `SEASON_MS = 1200` matches Chromium but is 2-3× low in Node under load. Eviction (`evictUniverseResults`) keeps up to ~2× `UNIVERSE_LIVE_RESULTS`: after 30 seasons 30 results were live and the page heap was 386 MB. `liveResults()` (`app.js:7612`) rehydrates every evicted season at once for Careers and the players export; at ~15 MB per result, 60 seasons ≈0.9 GB extra (extrapolated, not measured). Fix: stream seasons and release each as you go.

**UV14. Persistence payload. Low. VERIFIED.** A 30-season world stores 868K characters in localStorage (registry 277K, coachTree 246K, tail 235K). `coachTree.hires` is stored whole and unbounded (~8 KB/season); registry is capped at 300 entries and rows at 200, so it degrades quietly. At 100+ seasons `universeShed` triggers. Cap the tree by size.

**UV15. Returner seasons are dropped from the BBGM players export. VERIFIED by code (`app.js:4928`, `views.js:6262`).** An undrafted man who plays 2026-2028 has `laterSeasons` only in the player-page career table; `exportFile` writes only `priorSeasons`, so the players file loses them. The CLI can't write the players file (`bin/bbgmdraft.js:260`).

**UV16. UX nits. VERIFIED.** Loading three files does not enable universe mode (the checkbox must be ticked); the tab is a single scroll ~8,900px tall at 1400px wide with an unbounded "follow a program" dropdown of all 364 schools; Records reads "1 titles", "1 winners", "1 picks", "1 appearances", "1 seasons"; news says "{school} are national champions"; Hall-of-Fame and "Player of the 2030s" rows appear for a 6-season world.

**UV17. Seed identity is coarse. VERIFIED.** `fileFingerprint` samples 9 pids and names, so editing ratings (e.g. one player's `hgt`) leaves the fingerprint, the seed and `resultFingerprint` unchanged. An import cannot detect a doctored file.

**UV18. Empty or odd inputs are tolerated but silent. VERIFIED.** One file builds a 1-row world with 3 threads; two files claiming the same season both run and produce a 2-row same-year world; reversed order gives the same world.

### Improvements, ranked by value / effort

1. **UI1. Fix the POY pick and the Hall (UV1, UV8).** Small, high value: fixes the headline column, records, threads and news.
2. **UI2. Make saved universes visible after reload (UV2).** Small-medium: "restore from autosave" state, view-only Universe tab, per-file "reload class files" strip.

The tool is a college-season simulator that reworks a BBGM draft class: it writes college stats, awards and news and exports the class JSON. ### Proposed larger features

Effort: M = 1-2 weeks, L = 3-5 weeks, XL = 6+.

**F1. League write-back and "league patch" (deep BBGM integration). L.** Merge the reworked class(es) back into the original full league export: replace matching undrafted prospects by pid, keep every other row, preserve `version`, `gameAttributes`, `draftPicks`; keep "export class for Create New League"; add a "league doctor" report (pid collisions, missing fields, rows BBGM would migrate). Value: today users hand-merge classes; this turns a class tool into a league tool and lets a Universe chain rewrite a league's next three classes. Builds on `classesFromFile`, `state.league`, `exportFile`/`LEAGUE_ENVELOPE`, `pro.leagueDraft`, CLI `check`. Dependencies: a fixture library of real exports across BBGM versions; a schema validator mirroring `augmentPartialPlayer` with a version-aware writer; streaming/worker parsing for 100 MB+ `.json.gz`; gzip output. Risk: silent corruption of a user's league is the worst failure this tool can have (also schema drift, memory on 5,000-player leagues). Mitigate with a dry-run diff view, never overwriting the source, and a round-trip test (class in, league out, class re-extracted, hash equal).

**F2. Draft Night: real lottery types, picks and an interactive draft. L.** Support BBGM's `draftType` (NBA 2019 and 1994 lotteries, no lottery, reverse order, random), honour traded picks (`draftPicks` `tid`/`originalTid`), let the user pick for a team against AI teams using `pro.js`'s value model, output the draft order and write `draft`/`tid` via F1. Builds on `Pro.mockDraft`/`leagueDraft`, the Play tab's gating and scoring, `Rankings`, the board. Needs F1, a generalised and verified lottery (today's is a simplified fixed-weight pool), an a11y-reviewed draft-board UI. Scope to 3-4 common draft types.

**F3. Scouting game with fog of war. L.** A scouting budget, true ratings hidden behind per-scout noise, information revealed as engine phases run, scored by how the class's pro careers turn out years later. Builds on `play.js` (already gates views to "what was known before this phase"), `replay.js`, `Pro.projectClass`, the Universe chain. Needs F4 (otherwise "outcomes" are the invented model) and the worker move (F9a). Risk: balance, and reveal rules must never leak the true value.

**F4. BBGM-faithful development model calibrated to real league data. M-L.** Replace `pro.js`'s invented growth/decline/churn curves with a transcription of BBGM's `player.develop` (as `bbgm.js` does for `ovr`); add `tools/fit-bbgm.js` to ingest a user-supplied multi-season league export and check/tune peak ovr, career length and bust rate by pick slot, using a deterministic least-squares or table fit as `rolefit.js` does. Value: projections match what the game will do after import. Builds on `bbgm.js`, `calibration.js`, `tools/validate.js`, `rolefit.js`. The projection is derived, so no `ENGINE_REV` bump. Risk: upstream formula changes; add a documented "schema/formula watch" and a test pinned to the source commit.

**F5. Whole-league and historical-era generation. XL.** From a seed generate a complete BBGM league file: 30 teams, rosters, contracts and N seasons of prior classes via the Universe chain; add eras beyond `2009-2021` and `modern`. Needs F1, F2, F4, a contract/roster model the tool lacks, the worker architecture (F9a: 40 seasons at 3-6 s is minutes), and sourced anchors for new eras. Risk: scope explosion and calibration debt; frame it as a "league starter kit", not "simulate the NBA".

**F6. Data packs (a JSON, no-code extension system). L.** Move content out of code into validated, versioned JSON packs (college and conference tables, name pools, news/note templates, archetype tables, eras); pack hashes join the config fingerprint so a seed still reproduces. Builds on `config.js`, `colleges.js` (1.3k lines of data in code), the `calibration.js` era table, `text.js`, the service worker precache. Risks: determinism, template injection via names, a version contract to honour. Data only, never JavaScript.

**F7. Static community sharing (no backend). M.** A versioned seed gallery as static JSON in the repo (curated seeds with settings, par scores, `ENGINE_REV`, fingerprint) imported by URL or file; "class patch files" (locks and overrides) that export, import and show a merge diff; a "verify this share" check that says whether the recipient's engine reproduces the fingerprint. Builds on `replay.js`, `replaymeta.js`, Universe fingerprints, `readHash`, `applySettingsJson`. Needs a published format spec and a revision-mismatch policy. Low risk.

**F8. Class Forge: generate a draft class from scratch. M.** Turn `sample.js` (160 lines, one fixed generator) into a parameterised generator (archetype mix, nationality and name pools, class strength and top-end talent) feeding the existing engine. Builds on `sample.js`, `ratings.js`/`traits.js`, `validate.js` fixtures. Wants F6 for name pools. Low risk, easy to over-polish.

**F9. Engineering enablers (do before F1-F5).**
* **9a. Engine in a worker (L).** Make the runner's output serialisable or keep it in the worker and return view-sized results, so 5 s cold runs stop freezing the page and Universe scales.
* **9b. One-file release build (M).** esbuild concatenate-and-minify as a release artifact only (3.3 MB → 1.68 MB → 543 KB gzipped); keep the unbundled dev tree.
* **9c. Typed contracts without TypeScript (M).** JSDoc typedefs for `LeagueFile`, `Player`, `Result`, `Config`; `tsc --noEmit --checkJs` over pure modules in CI, added incrementally.
* **9d. Split `app.js` by tab (L, incremental).** Extract tab controllers (mock, universe, play) into `js/ui/*.js` against an explicit `state` API with change events.
* **9e. Test tiering (M).** A real fast tier under 5 minutes for PRs, the 20-minute suite nightly; make the `ui` job fail, not skip, when Playwright is absent in CI.
* **9f. Visual regression and axe (M).** Playwright screenshots of five views at two widths plus `@axe-core/playwright`; the a11y gate for F2/F3.
* **9g. Local diagnostics bundle (S).** One button copying `ENGINE_REV`, seed, settings, file fingerprint, UA and warnings; determinism makes "paste this" reproduce a bug.

### Roadmap

**Now (4-8 weeks): make the tool safe to grow and close the biggest integration gap.**
1. 9g, 9e, 9c first: cheap, and they unblock everything.
2. 9a (worker) and 9b (release build): measured wins, and F5 is impossible without the worker.
3. F1 (league write-back): the feature users most want that the tool declines to do. Build the fixture library and round-trip tests first, then the writer.
4. 9f (visual and axe) before any new complex UI.

**Next (2-4 months): make the loop a game, make projections trustworthy.**
5. F4 (BBGM-faithful develop and fit tool).
6. F2 (Draft Night) and F7 (community sharing), in parallel (F2 depends on F1).
7. F3 (scouting game) once F4 and 9a are in.
8. F8 (Class Forge) whenever there is a gap; 9d (split `app.js`) incrementally.

**Later (4+ months).**
9. F6 (data packs), after data has been extracted by F8's name pools and era tables stabilise.
10. F5 (whole-league generation), only after F1, F4, 9a and sourced anchors for new eras.

**What NOT to build**
* A backend, accounts or cloud sync: the offline, deterministic, zero-server design is the product. Share seeds and settings (F7), not data.
* A JavaScript plugin system: F6 must be data only; executable plugins turn an import tool into a code-execution surface.
* A full TypeScript rewrite or ES-module migration: it breaks `file://` and costs weeks for no user-visible gain. Use JSDoc types (9c) and a release bundle (9b).
* Localization: tens of thousands of lines of English templates with grammar helpers make it a rewrite for a small audience.
* Multi-sport (FBGM, hockey): ratings, stats, tournament and calibration are basketball-specific; revisit only after packs, as a separate fork.
* Real-time collaborative editing (needs a backend) and ML-based calibration (opacity in a deterministic tool; F4's deterministic fits do the same job).
* Real-player datasets or rosters: licensing and trust problems.
* Re-implementing BBGM's game simulation: the contract is "the class is right when it arrives".
